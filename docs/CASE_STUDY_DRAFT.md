## One-page business case
**Problem.** Before an invoice is paid, someone must confirm the goods were ordered (PO), received (receiving record) and billed correctly (invoice). In small and mid-size finance teams that is three PDFs compared by eye and re-keyed into a spreadsheet. The costly failures are paying twice, paying for goods not received, paying the wrong amount or currency, and paying a fraudster who slipped instructions into a document.

**Who benefits.** AP clerks (faster, fewer re-keys), controllers (configurable tolerances, separation of duties, an audit trail), purchasing leads (disputes arrive with the three numbers and the dollar exposure).

**What was built.** A local-first web app that reads the three documents, extracts fields with a pointer to the exact words on the original page, runs a deterministic line-level three-way match (partial receipts, split shipments, discounts, freight, tax, multi-currency policy, duplicates), explains each exception, lets a person correct or override with a recorded reason, enforces role/limit/separation-of-duties gates, and exports a CSV/XLSX review record. It never pays or posts.

**Evidence of the prior workflow.** `[YOUR EVIDENCE — e.g., interview notes, a timed manual comparison, an internship observation. None is claimed here.]` Manual baseline time: `[UNTESTED]`.

**Architecture in one paragraph.** PDF → pdf.js word boxes → deterministic rules extractor (optional Claude adapter behind a grounding check) → decimal-math reconciliation engine → typed exceptions → human review in a React UI → role-gated approval state machine → SQLite with an append-only audit table → file-only export. AI and money are separated by design: the engine has no model dependency, and the model (when enabled) can only propose grounded fields or reword explanations whose numbers are verified.

**Constraints and decisions.** Synthetic data only; no OCR (no engine installed); no live LLM (no key); demo identity instead of real auth; three layout families; exclusive sales tax only.

**Validated results (MEASURED, synthetic).** All 8 seeded discrepancies detected with the intended exception code and 0 false alarms on 17 clean bundles (baselines: total-only F1 50%, zero-tolerance F1 61.5%); field F1 100% on 72 documents; 112 unit/integration tests and 6 browser tests passing; invoice analysis ≈ 2 ms median. **Not measured:** human time saved, real-world accuracy, user satisfaction, LLM cost.

**Limitations.** See README → Known limitations. **Next steps.** Real-document evaluation set; OCR adapter; SSO and tamper-evident audit; PO/receipt import from CSV/ERP read-only adapter; VAT-inclusive and multi-rate tax; learning supplier-specific layouts with human corrections.
